# Как менять расписание

Основной файл — `data/personal/schedule.json`. `data/demo/` не изменяет личное расписание. Обновляйте только нужные записи, сохраняйте существующие ID и пользовательские заметки. `completions.json` меняет приложение; для обычного редактирования планов его трогать не нужно.

Личные файлы исключены из Git. В веб-версии импортируйте расписание через «Импорт и экспорт»; файл обрабатывается в браузере и не загружается на GitHub. Публичная сборка получает только пустой шаблон из `data/published/` и демонстрационные примеры.

## 30-дневный челлендж

Необязательное поле `challenge` в корне расписания:

```json
{
  "title": "30 дней",
  "startDate": "2026-11-08",
  "durationDays": 30
}
```

Первый день — дата начала, последний — `startDate + durationDays - 1`. В текущем плане это 8 ноября — 7 декабря 2026 года. До начала показывается дата старта, после окончания — завершение; счётчик не выходит за 30. Поддерживается длительность 1–366 дней. Даты начала отдельных задач независимы от начала челленджа.

«Сегодня» определяется на устройстве в Asia/Qyzylorda и обновляется автоматически. Изменение даты не требует публикации новой сборки. Если пользователь назовёт другую дату старта, измените `challenge` в его расписании; для пустого стартового шаблона сайта также в `data/published/schedule.json`.

## Минимальный пример

```json
{
  "schemaVersion": 1,
  "timezone": "Asia/Qyzylorda",
  "goals": [
    {
      "id": "health",
      "title": "Привести себя в форму",
      "type": "goal",
      "description": "Движение и питание",
      "color": "sage"
    }
  ],
  "activities": [
    {
      "id": "home-workout",
      "title": "Тренировка дома",
      "goalId": "health",
      "section": "Движение",
      "kind": "habit",
      "startDate": "2026-11-09",
      "endDate": "2026-11-22",
      "time": "18:00",
      "durationMinutes": 40,
      "recurrence": { "type": "weekly", "weekdays": [1, 3, 5] },
      "excludedDates": ["2026-11-11"],
      "notes": "Только заданная пользователем информация"
    }
  ]
}
```

ID уникальны внутри целей и внутри занятий. Формат: строчные латинские буквы, цифры, `_`, `-`, до 80 символов. Стабильные ID позволяют сохранять отметки при изменении названия, времени и заметки.

## Группы: цель, проблема или проект

Группа — большая категория, объединяющая несколько самостоятельных задач и привычек. Внутреннее имя массива `goals` и поле связи `goalId` сохранены для совместимости. В интерфейсе это раздел «Группы».

Поля: `id`, `title`, `description` (можно пустую строку), `color`, необязательный `type`:

- `goal` — цель, например «Привести себя в форму»;
- `problem` — проблема, например «Беспорядок на рабочем месте»;
- `project` — проект, например «Учиться новому».

Если `type` не указан, группа считается целью; старые расписания работают без изменений. ID `all` зарезервирован, не используйте его для группы.

Внутри группы задачи можно распределять по необязательным разделам через поле `section`, например «Движение» и «Питание». Отдельный справочник разделов не нужен: раздел появляется, когда на него ссылается задача. Без `section` задача остаётся прямо внутри группы. Если есть и именованные разделы, и задачи без раздела, последние показаны в «Общее». Без `goalId` задача видна в «Без группы».

Каждая задача хранит свои даты, время, повторение и длительность. У группы нет собственного расписания, медицинских назначений или общего переключателя выполнения. Счётчик на карточке — число задач, а не число повторений и не процент достижения цели.

Пример структуры: «Привести себя в форму» → «Движение» → разминка, тренировка, прогулка; та же группа → «Питание» → планирование питания. Для задач лечения используйте отдельные группы с переданными пользователем названиями и только фактически названными назначениями. Примеры из обсуждения не являются действующим расписанием.

Доступные цвета: `sage` — зелёный, `lavender` — сиреневый, `peach` — персиковый, `blue` — голубой, `rose` — розовый.

## Занятия, задачи и события

| Поле | Правило |
| --- | --- |
| `id`, `title` | Обязательны |
| `goalId` | ID существующей группы (цели, проблемы или проекта); можно опустить |
| `section` | Необязательное название раздела внутри группы, до 100 символов; требует `goalId` |
| `kind` | `habit` — привычка, `task` — задача, `event` — событие |
| `startDate` | Обязательная дата `ГГГГ-ММ-ДД` |
| `endDate` | Необязательная включительная дата окончания; без неё повторение бессрочное |
| `time` | Необязательное время `ЧЧ:ММ`, 00:00–23:59; без времени **поле опустить**, не ставить фиктивное время или null |
| `durationMinutes` | Обязательная длительность от 1 до 1440 минут |
| `recurrence` | Одно из правил ниже |
| `excludedDates` | Необязательный массив дат, когда занятие не состоится |
| `notes` | Необязательная заметка |

Поддерживаются действительные даты в пределах 1900–2199 годов. Если длительность не названа, для корректной шкалы времени уточните её; не выдумывайте назначения, дозировки или режим лекарств. Дата разовой задачи — её запланированный день/срок. Дела без времени видны отдельно и учитываются в общей сумме планов сегодня.

## Повторения

```json
{ "type": "once" }
```

Один раз, только в `startDate`. `endDate` опускается или совпадает с `startDate`.

```json
{ "type": "daily" }
```

Каждый день в пределах периода.

```json
{ "type": "weekly", "weekdays": [1, 3, 5] }
```

В указанные дни недели: 1 — пн, …, 7 — вс. Начало и конец периода не обязаны совпадать с днями выполнения.

```json
{ "type": "interval", "everyDays": 2 }
```

Раз в N календарных дней, начиная строго с `startDate`, через границы недель, месяцев и лет. «Через день» — 2. «Раз в три дня» — 3. Исключение пропускает конкретное занятие и не сдвигает последующие повторения.

## Исключения, переносы и отметки

- Пропустить занятие — добавить дату в `excludedDates`.
- Перенести одно повторение — исключить исходную дату и добавить отдельное разовое занятие с новым ID на новую дату. При наличии отметки на старую дату уточните, относится ли она к перенесённому занятию.
- Изменить будущую часть серии, сохранив прошлое — завершить старую серию накануне изменения и создать новую серию с новым ID. Не менять прошлое без запроса пользователя.
- Отметка имеет ключ `id@ГГГГ-ММ-ДД`. Отметить один день не значит завершить всю серию.
- При переносе задачи в другую группу или раздел меняйте только `goalId` / `section`, сохраняя её `id`: существующие отметки останутся на своих датах.
- После удаления занятия старые отметки сохраняются в файле, но больше не отображаются. Не используйте удалённый ID для другого занятия.
- Переход через полночь: `time: "23:40"`, `durationMinutes: 60` виден как 20 минут в первом дне и 40 минут во втором; отметка общая и относится к дате начала. Пересечения рассчитываются с учётом продолжения.

После изменений выполните `npm run check:data`, проверьте код/JSON. Сборка и тесты нужны после крупных изменений кода или перед пушем. Для изменения только данных сборка не требуется.
