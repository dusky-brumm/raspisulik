# Расписулик

Личный планер для целей, привычек и задач. Работает локально и на GitHub Pages. Расписание добавляется через чат Codex, в приложении его удобно смотреть и отмечать выполненное.

## GitHub Pages и 30 дней

Адрес публикации: **https://dusky-brumm.github.io/raspisulik/**.

Челлендж начинается **8 ноября 2026**, 30-й день — **7 декабря 2026**. Сегодняшняя дата и номер дня вычисляются при работе сайта в **Asia/Qyzylorda**. В полночь и при возвращении на вкладку данные обновляются автоматически; ежедневная сборка не нужна.

В веб-версии **Мои планы** и отметки хранятся в текущем браузере. Через кнопку с дискетой можно импортировать расписание из JSON или экспортировать резервную копию. Импорт обычного расписания сохраняет отметки; полная резервная копия восстанавливает оба набора данных. Автоматической синхронизации между телефоном и компьютером нет — используйте файл экспорта/импорта.

Публичный сайт содержит только пустой стартовый шаблон и нейтральное демо. Личные группы, задачи и отметки не попадают в репозиторий или в сборку Pages. На Pages первым открывается «Мои планы», локально — «Демо»; выбор запоминается.

```powershell
npm run build:pages    # Статическая сборка с базовым путём /raspisulik/
npm run check:pages    # Ресурсы, шаблон и исключение личных данных
npm run preview:pages  # http://127.0.0.1:4174/raspisulik/
```

Публикация: исходники сохраняются в `codex/github-pages`, а `npm run deploy:pages` собирает и отправляет сайт в `gh-pages`. Pages публикует корень этой ветки. Требуется настроенный GitHub CLI; токены не хранятся в приложении. При другом имени репозитория задайте `PAGES_BASE` перед сборкой.

## Открыть приложение

Дважды щёлкните **Запустить.cmd** в папке проекта. Он поднимет приложение в фоне и откроет браузер. Повторный запуск откроет уже работающий экземпляр.

Адрес: **http://127.0.0.1:4173**. Для установки нужен Node.js 22.18 или новее.

Первоначальная установка (в этом проекте уже выполнена):

```powershell
npm install
npm run build
npm start
```

`npm start` запускает собранное приложение. Пока это окно терминала открыто, сервер работает; Ctrl+C его останавливает. Для разработки: `npm run dev` (тот же адрес, с обновлением интерфейса). Не запускайте два сервера на одном порту.

При первом запуске после клонирования отсутствующее личное расписание создаётся из пустого шаблона. Существующий файл не перезаписывается.

При запуске через `Запустить.cmd` сервер работает до перезагрузки компьютера. Его можно завершить через Диспетчер задач (процесс Node.js); PID и журнал доступны в `.local/`. Другие процессы Node.js могут принадлежать другим приложениям.

## Как пользоваться

- **Таймлайн:** период занятия показан светлой полосой, конкретные повторения — цветными отметками. На маленьком экране таблица прокручивается горизонтально. Нажатие на дату открывает день, на отметку — подробности и выполнение.
- **День:** расположение занятий по часам, пересечения и отдельный список дел без времени. Переходящие через полночь события видны в обоих днях; отметка относится к дате начала.
- **Календарь:** месяц целиком; нажмите на день, чтобы увидеть все занятия. На телефоне события показаны цветными точками.
- **Группы:** цель, проблема или проект объединяют несколько задач. Откройте карточку, чтобы увидеть задачи по разделам, например «Движение» и «Питание». Переключатель «Таймлайн» показывает их расписание. Задачи без группы доступны отдельной карточкой. Число на карточке — количество задач, а не повторений и не процент достижения цели.
- **Задачи:** повторения за последние 7 дней и следующие 30 дней, а также все более ранние просроченные разовые дела. Раздел «Выполненные» также включает старые отметки, если занятие ещё существует в расписании.
- **Видео:** подборки роликов для зарядки и других занятий. Создайте подборку, выберите несколько файлов или папку. Не-видео пропускаются; повторный выбор тех же файлов не создаёт дубликаты. Названия берутся из файлов, порядок — из имён с учётом чисел. Карандаш открывает переименование, порядок и «Убрать»; убранное можно вернуть вместе с отметками.

В подборке есть встроенный проигрыватель и отдельная галочка на каждый ролик за выбранный день. «Выполнено и дальше» отмечает текущий ролик и открывает следующий; сам просмотр не ставит галочку. Подборку можно связать с одной задачей в расписании — через форму создания или «Название и связь с задачей». После отметки всех роликов задача за этот день завершается; снятие отметки снова открывает её. Это применяется только к дням, когда задача запланирована. Из подробностей задачи подборка открывается кнопкой «Видео для занятия».

Видео, названия подборок и отметки роликов сохраняются в **IndexedDB текущего браузера**, как в локальном режиме, так и на Pages. Они не загружаются на сервер и не попадают в GitHub. Выбор папки копирует её видео в хранилище, а не следит за дальнейшими изменениями папки. Исходные файлы не меняются. Сохраняйте их: очистка данных браузера удаляет видеотеку, JSON-экспорт расписания не содержит подборок и отметок роликов. Локальная версия и Pages используют разные хранилища. Доступное место и поддержка формата зависят от браузера; для воспроизведения подходят MP4/H.264 и WebM.

Фильтр группы применяется к таймлайну, дню, календарю и списку. На общем таймлайне задачи объединены по группам и разделам; на заголовок группы можно нажать. Сводка в разделе «День» относится к выбранной дате.

**Демо** в переключателе открывает нейтральные примеры на ноябрь 2026 года. **Мои планы** открывает личное расписание. Демо не является личными назначениями.

## Как добавлять планы через чат

Например: «Добавь цель “Здоровье”. С 9 по 22 ноября 2026 года тренировка по пн, ср и пт в 18:00, 40 минут. 11 ноября пропускаю». Или: «10 ноября разобрать стол, 25 минут, без точного времени».

Можно сказать: «В цель “Привести себя в форму”, в раздел “Движение” добавь прогулку». Для объединения задач подходят также «проблема» и «проект». Раздел можно не задавать. При переносе существующей задачи в другую группу её отметки сохраняются.

Codex меняет **data/personal/schedule.json**. В локальной версии нажмите обновление наверху планера или обновите страницу. В версии Pages импортируйте этот файл через кнопку с дискетой: он остаётся в браузере, существующие отметки сохраняются. Пересборка после изменения личного расписания не нужна.

Формат данных, повторения и исключения описаны в [DATA.md](DATA.md). Для дальнейшей работы с проектом — [AGENTS.md](AGENTS.md).

## Хранение и проверка

| Файл | Содержимое |
| --- | --- |
| `data/personal/schedule.json` | Ваши цели и расписание, редактирует Codex |
| `data/personal/completions.json` | Ваши отметки, автоматически создаёт приложение |
| `data/demo/schedule.json` | Отдельный демонстрационный набор |
| `data/demo/completions.json` | Отметки для демо, отдельно от личных |
| `data/published/schedule.json` | Пустой шаблон с датами челленджа для Pages |

Расписание и отметки — разные файлы одного локального хранилища. Отметки привязаны к стабильному ID занятия и дате: изменение названия или времени их не сбрасывает. Приложение читает расписание с диска и никогда не перезаписывает его. Записи отметок выполняются последовательно и заменяют файл атомарно. При ошибке JSON исходные данные остаются на месте, а интерфейс показывает причину.

Для локальной резервной копии расписания и его отметок скопируйте папку `data` при остановленном приложении. Личное расписание и файлы отметок исключены из Git. В Pages их резервная копия делается кнопкой экспорта. Видеоподборки хранятся в браузере отдельно, как описано в разделе «Видео» выше.

Часовой пояс: **Asia/Qyzylorda**. Неделя начинается с понедельника. Даты начала и окончания включены в период. Все даты хранятся как местные календарные даты, без пересчёта в часовой пояс браузера.

```powershell
npm run check:data  # Проверить расписания после изменения данных
npm run build       # TypeScript и итоговая сборка после изменения кода
npm test            # Повторения, время, валидация и надёжность хранения
```

Стек: React, TypeScript, Vite; небольшой Node.js-сервер для чтения JSON и сохранения отметок. Сервер слушает только 127.0.0.1. Шрифт Inter с кириллицей включён в сборку; внешние шрифтовые сервисы и CDN при работе не используются.

Оформление следует переданному пользователем дизайн-коду: база #F4F6F7, лёд #DCE8F2, лаванда #E8E3EF, текст #273548, вторичный текст #5E6B7E, акцент #496FA6; Inter 400/500; матовые поверхности с заливкой white .56, обводкой white .65, blur(24px) saturate(110%). Пояснения доступны через кнопку «Как добавить» и подробности занятия, без постоянных служебных блоков.
