# Расписулик

Проверяй сборку, запускай тесты только после крупных изменений или перед пушем на Git. После небольших правок проверяй код и качество кода без повторного запуска всех проверок.

## Работа с расписанием

- Пользователь надиктовывает планы в чате; редактируй `data/personal/schedule.json` по [DATA.md](DATA.md).
- Цель, проблема и проект — типы одной большой группы (`goals[].type`: `goal`, `problem`, `project`). Внутри несколько самостоятельных задач. `goalId` связывает задачу с группой; необязательное `section` распределяет задачи по разделам, например «Движение» и «Питание». Названия разделов не обязательны и задаются пользователем.
- При переносе задачи между группами или разделами сохраняй её ID. Группа не является одним занятием и не завершается общей галочкой. Примеры проблем и лекарств из разговора не считай реальными назначениями или готовым расписанием.
- Сохраняй существующие ID и данные вне запроса. Не трогай `completions.json`: приложение само сохраняет отметки по датам, отдельно от расписания.
- Без названного времени опускай `time`. Недостающие даты и длительность уточняй, если их нельзя уверенно вывести из контекста. Относительные даты считай в Asia/Qyzylorda.
- Не придумывай назначения, дозировки и режимы лекарств. Добавляй только переданные пользователем данные.
- Периоды включают обе границы. Для разового изменения серии используй исключение и отдельную запись, для новой будущей части — разделение серии; сохраняй историю.
- После изменения JSON достаточно `npm run check:data`. После изменений расписания не нужна пересборка.
- Демо находится в `data/demo/`, личные данные — в `data/personal/`. Не копируй демо в личные данные без запроса.
- Челлендж пока на 30 дней: начало 2026-11-08, последний день 2026-12-07 включительно. `challenge` хранит название, дату начала и `durationDays`. Сегодня и номер дня вычисляются в Asia/Qyzylorda при работе приложения, без ежедневной пересборки.

## GitHub Pages

- Пользователь запросил публикацию на GitHub Pages. Адрес проекта: `https://dusky-brumm.github.io/raspisulik/`.
- Сборка `npm run build:pages` создаёт `dist-pages/`, `npm run check:pages` проверяет пути и исключение личных данных. `npm run preview:pages` открывает локальную статическую проверку на 4174.
- `data/personal/` — приватные файлы, исключены из Git. Никогда не добавляй их принудительно и не копируй в статическую сборку. Публикуются только пустой шаблон `data/published/schedule.json` и нейтральное демо. Нельзя помещать реальные назначения в публичное демо или шаблон.
- На Pages расписание и отметки сохраняются в браузере. После изменения личного расписания через чат можно импортировать `data/personal/schedule.json` через кнопку «Импорт и экспорт» в открытом сайте. Обычный импорт сохраняет отметки; полная резервная копия переносит и расписание, и отметки. Между устройствами автоматической синхронизации нет.
- Исходники — ветка `codex/github-pages`, публикация — автоматически собранная `gh-pages`. Перед публикацией сохрани проверенные изменения исходников коммитом, затем `npm run deploy:pages`. Скрипт использует отдельный индекс Git и обычный fast-forward push, не меняя рабочую ветку и её индекс.
- Не вставляй GitHub-токены в клиент и не добавляй личные данные в репозиторий ради синхронизации.

## Код

YouTube-ролики добавляются через кнопку «YouTube» в подборке, только по переданной пользователем ссылке. `youtubeIdFromUrl` проверяет протокол и официальный домен, `addYouTube` добавляет в конец и при повторе сохраняет ID и галочки. Сами ролики не скачиваются. Не публикуй личные подборки в шаблоне Pages ради добавления ссылки: изменяй локальное расписание и используй интерфейс открытого сайта для пользовательского хранилища. Если длительность ролика известна, для сетки округляй её вверх до целых минут, указывая фактическую длительность в заметке.

Видеоподборки — `src/VideoLibrary.tsx`, хранилище IndexedDB — `src/video-store.ts`. Содержимое видео, метаданные, порядок и отметки по датам остаются в браузере пользователя и не входят в файлы расписания или JSON-экспорт. Никогда не добавляй личные видео в репозиторий или статическую сборку. К задаче можно привязать одну подборку. Индивидуальная галочка или «Выполнено и дальше» меняет отметку ролика, затем обновляет выполнение связанной задачи, только если она запланирована на этот день. Смотреть видео не означает выполнить упражнение. Переименование и перестановка сохраняют ID и отметки. «Убрать» обратимо через список убранных, без удаления исходных файлов и истории. После добавления реальных файлов не перемещай и не удаляй их без запроса.

React + TypeScript + Vite, локальный Node.js-сервер и отдельный статический режим Pages. Доменная логика — `src/domain.ts`, файловое хранилище — `server/storage.mjs`, браузерное — `src/browser-storage.ts`, выбор режима — `src/data-client.ts`. `npm run build` проверяет TypeScript и собирает локальную версию. `npm test` проверяет даты, повторения, группы и оба хранилища, не меняя личные данные. `npm start` запускает локальную собранную версию, `npm run dev` — разработку.
